# Восстановление производного CSV GRE — 1.0.0

Дополнение требует установленный `switzerland_climate.py` версии 1.0.1.
Python 3.10+, стандартная библиотека. Сеть для восстановления не используется.

В приложенном производном файле `2e8c8fd0e4f5ad1537c427af.csv.gz` обнаружено
ровно одно отличие от повторной обработки зафиксированного оригинала:
в строке 45290 за `2025-03-02T00:00Z` байт запятой `44` заменён на `40` (`(`).
Из-за этого строка содержит 37 полей вместо 38. Исходный CSV поставщика имеет
корректные 36 нативных полей; добавление двух временных полей даёт 38.

SHA-256 распакованного оригинала совпадает с планом:
`2f77e7cddb83d6a8578fba2300e35782538412092a4eaa7ec7ac7487c8c609d0`.
Проверка обеих gzip-обёрток пройдена. Причина и момент изменения одного байта
по этим файлам не установлены. Совпадение производного файла с его старым
receipt не гарантирует совпадение с оригиналом поставщика.

## Запуск

Распакуйте дополнение в `Database/CH`, рядом с существующими
`switzerland_climate.py`, `plan.json` и `downloaded`. Выполните:

```bat
python switzerland_repair.py --plan plan.json --out downloaded --job-id 2e8c8fd0e4f5ad1537c427af
```

Инструмент проверяет SHA-256 исходного CSV по зафиксированному STAC, заново
создаёт производную часть и метаданные во временной папке и проверяет все строки.
Затем сохраняет старые CSV, метаданные и receipt в `repair_history`, обновляет
производные файлы и записывает новый receipt последним. Исходный gzip и план
не перезаписываются. При несовпадении оригинала с зафиксированным SHA-256
операция прекращается без сетевой загрузки.

Ожидаемый итог для GRE:

```json
{
  "selected_rows": 52608,
  "columns": 38,
  "network_requests": 0,
  "original_preserved": true,
  "repaired": true,
  "different_plain_bytes": 1
}
```

Повтор той же команды возвращает `already_consistent: true`, `repaired: false`.
Строки, значения, единицы и QC не подбираются и не заполняются: производная
таблица полностью воспроизводится из проверенного оригинала.

Для E0 используйте также обновление расчётной программы 0.1.2: оно учитывает
проверенные дополнительные планы DE. Старые результаты остаются отдельными;
новая подготовка данных создаёт новый run. Контроль C этим исправлением не
оценивается. Сравнение цепочек RH/ln(e)/q в это дополнение не включено.
