# IGE — интерполяционные эксперименты 0.3.0

Новая программа выполняет 73 сравнения на уже подготовленном численном кубе: 9 моделей T, 4 модели p и 60 вариантов влажности. Полный протокол и последующие солнечный, осадочный и ветровой блоки описаны в `INTERPOLATION_PROGRAM_v030_RU.md`.

Это обновление существующей папки IGE Automatic Regression / Humidity 0.2.1. Распакуйте файлы рядом с `ige_humidity.py`. Ваши `config_auto_regression.json`, Database и предыдущие результаты не входят в обновление и не перезаписываются. Нужны Python 3.10+ и уже установленные numpy/scipy из `requirements_regression.txt`.

Запуск двойным щелчком: `RUN_INTERPOLATION_V030.bat`. Он использует `.venv_regression`, если она есть. Новые зависимости BAT не устанавливает.

Источник по умолчанию — `humidity_results/20261108T194858_552399Z_abe8e77a`, то есть ваш завершённый запуск 0.2.1. Он должен содержать `cube`, `checkpoints`, `run_spec.sealed.json`, `summary.json`. Если папка называется иначе, измените только `source_run` в `config_interpolation_v030.json` или передайте её явно:

```text
python ige_next_experiments.py run --config config_interpolation_v030.json --source-run "humidity_results/имя_запуска"
```

В JSON используйте прямой `/` для путей Windows. Расчётные файлы создаются в новой папке `interpolation_experiments/дата_и_ID`. Исходный куб копируется и проверяется; повторное сканирование Database и интернет не нужны.

Для продолжения после остановки:

```text
python ige_next_experiments.py resume --run "interpolation_experiments/имя_нового_запуска"
```

Завершённые кандидаты проверяются по хешам и переиспользуются. Если изменились код, конфигурация или протокол, создайте новый запуск. Не исправляйте `run_spec.sealed.json` вручную. Неразрешённая оптимизация сохраняется как результат, а не исчезает из общей матрицы.

Основные выходы: `REPORT_RU.md`, `summary.json`, `comparison.csv`, `coupling_diagnostic.json`. Для каждой модели доступны D-коэффициенты, параметры доноров, трасса настройки и прогнозы V (`V_predictions.csv.gz`, точные массивы и веса в `V_predictions.npz`). Расшифровки QC, источников, ID станций и времени — `input_codebooks.json` и `cube/metadata.json`.

Основное сравнение использует одинаковые часы внутри блока. Для влажности joint и own **переобучаются отдельно**. Собственное покрытие выводится дополнительно. Единицы ошибки влажности — процентные пункты RH. Метрики температуры и давления относятся к их собственным общим маскам, поэтому не следует автоматически сравнивать их с прежними числами на 6672 часах влажности.

Реальные данные здесь — пилот выбранных станций/дней из AT/DE/CH, а не весь национальный каталог. Неполные годы допустимы. V уже просматривалась ранее: это исследовательское сравнение, не независимое подтверждение. C не вычисляется, команды открытия C в этой программе нет. Новый результат D+V также не обучается.

Солнечные, осадочные, ветровые, снежные и длинноволновые методы имеют статус ожидания входных данных в этом кубе. Полный план их проверки включён в протокол; текущий модуль не объявляет эти этапы выполненными.

Техническая проверка разработчика:

```text
python -m unittest discover -s tests -v
python tests/validate_next.py
```

186 автоматических тестов и полная синтетическая матрица 73/73 прошли при подготовке этой версии. Они проверяют реализацию, но не заменяют оценку точности по реальным наблюдениям. Пример реального запуска и его метрики публикуются отдельно с ID входного куба и спецификации.
