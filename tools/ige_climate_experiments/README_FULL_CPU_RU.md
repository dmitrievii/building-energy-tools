# IGE — эксперименты на полном календаре, CPU 0.4.0

Программа готовит данные AT/DE/CH из ваших загрузчиков и сравнивает пространственные модели температуры, станционного давления и влажности. Итоговые коэффициенты обучаются на **всех доступных допустимых часах всех обучающих станций D**, без прежнего лимита 12 000 случаев и без требования полного года. Для поиска гиперпараметров используется отдельно объявленная подвыборка D. GPU не используется и не устанавливается.

## Размещение и запуск Windows

Распакуйте архив рядом с существующими папками:

```text
Climate/
  Database/AT, DE, CH
  IGE_Automatic_Regression_v0_1_0/  (сохранить прежние результаты с cube/)
  IGE_Climate_Experiments_CPU_v0_4_0/
```

Ничего не копируйте поверх прежних результатов. По умолчанию `database` равна `../Database`. Если нужен абсолютный путь, используйте `/`: `E:/User Folder/Documents/00_TU Graz/Dissertation/IGE/Climate/Database`.

Запустите последовательно:

1. **1_PREPARE_FULL_DATA.bat** — создаёт отдельное окружение Python, проверяет квитанции, формирует хранилище всех календарных часов и показывает численность/оценку памяти. Этот этап читает большой объём данных.
2. **2_RUN_BASELINE_CPU.bat** — 10 базовых моделей, без новых городских признаков.
3. **3_RUN_URBAN_CPU.bat** — автоматически собирает реальные признаки покрытия земли вокруг станций, затем запускает 12 вариантов с окружением и 6 базовых двойников на тех же данных.
4. **4_EXPORT_REPORTS.bat** — создаёт `full_cpu_results/FULL_CPU_REPORTS.zip`; этот небольшой архив можно прислать для анализа.

Второй и третий расчётные этапы выполняйте последовательно: у них свои параллельные CPU-процессы. По умолчанию одновременно работают до двух независимых модельных задач, по одному потоку BLAS на процесс. Основные общие вспомогательные модели готовятся до этих задач и повторно используются.

Python 3.11–3.13; для вашего Windows/Python 3.12 менять конфигурацию не требуется. Завершение полной Database здесь не заявляется: она находится на вашем компьютере. Локальные проверки программы и ограниченный replay прежнего реального прогона находятся в `validation/`.

## Что изменилось

| Пилот 0.3 | Эксперимент 0.4 |
|---|---|
| Два дня каждого месяца | Полный календарь выбранных лет, включая 29 февраля и последние дни месяца |
| 24 площадки на страну | Все станции с подходящими исходными частями и опубликованной геометрией |
| До 12 000 расчетных случаев | Все доступные часы D в финальном обучении коэффициентов |
| Большие общие матрицы | Файлы станций на диске, блоки по 744 часа и последовательный QR |
| Без окружения станции | Покрытия поверхности в буферах 500 и 2000 м |

Станция участвует там, где есть наблюдение нужной величины и минимум два независимых допустимых донора. Отсутствующие значения сохраняются. Неполный год не исключает доступные часы. Все опубликованные конечные значения QC допустимы по умолчанию; отсутствие ручной проверки не означает плохое измерение. Точные исключения можно задать через `rejected_native_qc`.

## Обучение, выбор вариантов и контроль

- **D:** 2016–2022. Внутри D — пространственные группы семейств станций и непересекающиеся блоки лет.
- **V:** 2023 и 2024. Это исследовательская проверка вариантов; V не является окончательной независимой C.
- **C:** 2025 и исходные C-семейства сохраняются. Команды оценки C в этой версии нет.
- Исходные роли прежних семейств сохраняются. Новые станции получают роли детерминированно по метаданным. Совмещённые площадки и псевдонимы не могут незаметно попасть в другую роль.
- Прежний anchor ищется автоматически по кубу `883e3199cd68ef226090c8a2ed64ccbb32c4c395957a7ccab538919f1691b183`. При необходимости укажите в `cohort_anchor` путь к прежнему `cube/split.sealed.json`.

Поиск гиперпараметров: до 24 целей на страну и 48 заранее выбранных часов каждого месяца D. В городской панели выбор целей учитывает высотные квантили и квантили запечатанности поверхности. Отбор не смотрит ошибки или значения погоды. Эти ограничения относятся **только к поиску параметров**. После него коэффициенты выбранной структуры заново рассчитываются на всех доступных D-часах и D-станциях. Фактические числа сохраняются в `fit_rows`, `fit_stations`, `actual_fit_cases_by_year`.

Экспонента расстояния, штраф по разности высот и регуляризация ищутся непрерывной оптимизацией. Коэффициенты поправок находятся методом наименьших квадратов с регуляризацией и масштабированием признаков. Старые метеорологические коэффициенты не подставляются. Сходимость локального поиска не называется доказательством глобального оптимума. Неразрешённый поиск помечается ошибкой и не выдаётся за успешную модель.

## Городское окружение

Автоматически сохраняются гистограммы официальных продуктов Copernicus:

| Признак | Источник | Масштабы |
|---|---|---|
| Доля запечатанных поверхностей | Imperviousness Density 2018 | 500 / 2000 м |
| Плотность крон деревьев | Tree Cover Density 2018 | 500 / 2000 м |
| Постоянная/временная открытая вода | Water and Wetness 2018 | 500 / 2000 м |
| Постоянные/временные влажные поверхности | Water and Wetness 2018 | 500 / 2000 м |

Плотность крон **не равна всей растительности**: отдельного признака травяного покрова здесь нет. Карты являются фиксированным приближением окружения 2018 года, а не подтверждённой историей каждой площадки. Water and Wetness описывает период 2012–2018. Классы качества, исходные ответы, запросы и хеши сохраняются. Неизвестное покрытие не заменяется нулём. У карт есть собственные ограничения точности; их пользу проверяет эксперимент.

Первые графические запросы не требуют учётной записи. Всего нужно до шести небольших запросов на станцию. Ответы кешируются; повторный запуск продолжает незавершённый сбор. Время всей загрузки зависит от числа станций и сервиса; `preflight` показывает число запросов, но не обещает время окончания. Изменение радиусов/порога покрытия требует отдельного хранилища результатов, чтобы не переписать замороженные признаки.

Учитывается **разность признаков целевой точки и взвешенного окружения доноров**. Никакая фиксированная добавка «город = +2°C» не задана. Для городской поправки доступны постоянная зависимость и взаимодействия с годовым/суточным ходом. LCZ, высоты зданий, ветер и облачность в 0.4 не добавлены.

## Какие варианты сравниваются

База: T с постоянной, месячной и гармонической высотной поправкой; p с постоянной и месячной поправкой; пять маршрутов RH — напрямую, через ln(e), q, Td и T−Td. Давление — станционное в hPa. q — kg/kg влажного воздуха. Используется единая формула насыщения Buck над жидкой водой; обратная Td объявлена в диапазоне −80…+50°C.

Городской эксперимент: две модели T; для каждого из пяти маршрутов влажности — поправка только вспомогательной T и поправка T вместе с полем влажности. Все городские модели получают базового двойника на панели `urban_common` с теми же станциями, допустимыми донорами и часами. Выигрыш городского признака следует сравнивать **внутри этой панели**, а не с более полной панелью `all`.

Вспомогательные T/p для влажности общие между маршрутами с одной базой температуры. В каждом внешнем D-фолде их собственный поиск выполняется только внутри обучающей части этого фолда. Наблюдаемая T целевой станции не используется как вход восстановления RH. Для прямой RH улучшение вспомогательной T само по себе не должно менять прогноз — это контрольная структура.

Прямая RH не требует вспомогательных моделей T/p: их неуспешная оптимизация не блокирует этот независимый вариант.

Предельные расстояния/высоты/число доноров заданы в `donors`: по умолчанию 250 км, 2500 м, 64 кандидата, до 12 доноров. Доноры пока из той же страны и с согласованным исходным оператором измерения. Сравнивать 0.4 с прежним 0.3 как чистый эффект размера выборки нельзя: изменились также схема расчёта и некоторые ограничения доноров.

## Результаты и возобновление

В каждом запуске: `REPORT_RU.md`, `summary.json`, `comparison.csv`, спецификация, графики PNG/SVG. У каждой модели:

- коэффициенты, имена/масштабы признаков и ранг;
- общий MAE, RMSE, bias, численность, месячные и трёхчасовые срезы;
- полные почасовые ошибки V в `V_predictions.csv.gz`, наблюдаемые T/RH/p, вспомогательные T/p и исходные QC-коды;
- частоты знаковой ошибки, включая хвосты, и отдельные строки по станциям.

Частоты и основные ошибки выровнены по странам и станциям. Месячный состав может меняться — это отмечено в отчёте и численности. RH не обрезается до 0–100%. Нефинитный прогноз на обязательной маске делает вариант неуспешным, а не исчезает из оценки. Допуск в EPW и заполнение пропусков не выполняются.

Повторите тот же BAT после прерывания: подготовленные части, завершённые модели и QR-части финального обучения повторно используются после проверки. Изменение модели/кода/конфигурации создаёт отдельный эксперимент. Если процесс аварийно закрыт, а файл `.lock` остался, убедитесь, что соответствующий Python уже завершён, и удалите **только указанный в сообщении lock-файл**. Затем повторите команду.

`FULL_CPU_REPORTS.zip` не включает Database, полный файловый кеш или многогигабайтные почасовые прогнозы. Для разбора конкретных часов дополнительно понадобится `V_predictions.csv.gz` нужной модели.

Команды без BAT:

```console
python ige_full_experiments.py prepare --config config_full_cpu.json
python ige_full_experiments.py preflight --config config_full_cpu.json
python ige_full_experiments.py run --config config_full_cpu.json --suite baseline
python ige_full_experiments.py urban --config config_full_cpu.json
python ige_full_experiments.py run --config config_full_cpu.json --suite urban
python ige_full_experiments.py export --config config_full_cpu.json
```

Тесты: `python -m unittest discover -s tests -p test_full_cpu.py -v`. Инженерный импорт прежнего архива: `import-pilot --source-run PATH`; он явно помечается как разреженный replay и не называется полной Database.
