# IGE: программа проверки пространственной интерполяции, версия 0.3.0

Дата регистрации: 08.11.2026. Область: синхронные почасовые наблюдения AT/DE/CH.

## 1. Исследовательский вопрос и границы вывода

Нужно определить, какие модели восстанавливают наблюдения в исключённой из доноров точке с наименьшей ошибкой при заданном покрытии, и насколько выбор меняется по времени года, высоте, расстоянию и доступности переменных. Сравниваются прогнозы конкретных часов. Генерация типичного года из месячной климатологии, временное заполнение пропусков и прогноз будущего климата являются отдельными задачами. Результат этой программы сам по себе не допускает EPW к энергетическим расчётам.

Станция с неполным годом остаётся источником и объектом проверки в каждый доступный час. Отсутствие ручной проверки не означает ошибочное наблюдение. Сохраняются исходные QC-коды; первичная допустимость наследуется от проверенного куба данных. Дополнительные произвольные веса доверия и фильтр полного года не вводятся. Известные пропуски, несовместимость операторов измерения и нарушения физического домена учитываются явно.

Это **исследовательское расширение после предыдущего просмотра V**, а не новая независимая валидация. Нельзя многократно выбирать модели на V и затем называть преимущество на ней подтверждённым. C остаётся контрольной частью; её вычисление в новом модуле отсутствует. Исходные контейнеры уже автоматически читались при подготовке куба: речь идёт о вычислительном удержании, а не о слепом доступе к сырым файлам. Если доступен только архив результатов, проверка исходного внешнего маркера C может быть невозможна; это отмечается в спецификации.

## 2. Источники и воспроизводимость

Предпосылка E0: задания загрузки разрешены с учётом версий восстановления, хеши производных файлов проверены, происхождение и единицы сохранены. Полнота передачи файлов не равна полноте метеорологического ряда. Изменённые DWD ZIP не подменяют исходную замороженную версию; замена должна иметь явную связь происхождения. Новая программа не загружает сеть и не исправляет Database.

Исполняемый блок использует проверяемый численный куб завершённого сравнения влажности 0.2.1 и его замороженное разбиение. Копируются массивы, спецификация связывает cube_id, split_id, source_spec_id, D-контрольные точки T/p, исходные хеши, полный список кандидатов, код, этот протокол, конфигурацию и среду. Нельзя продолжить результат после изменения кода или протокола. Кандидат сохраняется отдельно с оптимизацией, коэффициентами, прогнозами, весами доноров и хешами. Неудачные кандидаты остаются в отчёте. Код не выполняет итоговое переобучение D+V: отчётные прогнозы V получены моделями D.

Исходный пилот: 72 семейства, 74 ID, по 24 семейства на страну. D: 42 семейства/43 ID, годы 2019–2021; V: 15/15, 2023; C: 15/16, 2025. В каждом месяце выбраны 15–16 числа, 576 часов/год. Предварительная равномерная выборка по станции и месяцу ограничена 12000 случаев на часть. Это не непрерывный десятилетний ряд и не репрезентативная выборка экстремумов. Численность и состав на конкретном запуске читаются из его замороженной спецификации, а не навязываются этим примером.

## 3. Общая математическая схема и подбор параметров

Для доступных доноров j в час t:

\[
\widehat y_{it}=\sum_j w_{ijt}(\theta)y_{jt}+x_{it}(\theta)^T\beta,
\quad \sum_j w_{ijt}=1.
\]

Используются доноры той же страны и совместимого оператора измерения. Семейство проверяемой станции полностью исключается. При нескольких ID одного семейства доступен не более одного донора на час: выбирается ближайший из допустимых. Совпадающие площадки в пределах 0.1 km исключаются. Это первый контролируемый блок; трансграничный поиск проверяется позднее после унификации операторов, а не подразумевается автоматически.

IDW: \(r_j^2=d_j^2+(a_z\Delta z_j)^2\), \(w_j\propto r_j^{-b}\). d в km, Δz в km, a_z в km/km. Gaussian: \(w_j\propto\exp[-r_j^2/(2\ell^2)]\). Параметры b, ln(a_z), ln(ell) определяются непрерывной оптимизацией. Начальные точки — численная диагностика локального оптимума, а не перебор коэффициентов. Границы b=[0.1,8], ln(a_z)=[−6,7]; для Gaussian диапазон ell задаётся геометрией D. Попадание на границу сохраняется. Глобальный минимум не гарантируется.

При фиксированных нелинейных параметрах коэффициенты β оцениваются взвешенной SVD-регрессией. Ridge применяется после RMS-нормировки признаков; ln(lambda) оптимизируется в [−14,4]. Полный численный ранг и ограничение числа обусловленности обязательны даже для ridge: регуляризация не выдаётся за идентифицируемость. Для Huber масштаб берётся только из остатков OLS обучающей части, заново для рассматриваемых весов; он не зависит от контрольных остатков. Это отличается от прежней реализации с замороженным для внутренней части масштабом и явно относится к новой версии.

Внутри D проводятся три исключения групп семейств. Для каждого набора нелинейных параметров регрессия заново обучается на внутренней обучающей части и прогнозирует исключённые семейства. Критерий — MSE с равными весами стран, станций и представленных месяцев. Для влажности минимизируется MSE **восстановленной RH**, делённой на 100, а коэффициенты по-прежнему оцениваются в нативной координате. Сравнивать минимумы ошибок q и RH в разных единицах нельзя. V используется только для выбора структуры по macro MAE: сначала среднее по часам станции, затем по станциям страны, затем по странам. Это отличается от равенства месяцев во внутренней настройке и указано заранее.

Фиксированные контрольные маски определяются до подбора моделей. Если прогноз на одном из обязательных часов не конечен, час не исчезает из оценки: кандидат получает INCOMPLETE_COMMON_V. Для основного сравнения требуется не менее двух независимых допустимых доноров; этот же порог применяется к эталону ближайшей станции. Возможность работы с единственным донором — отдельный тест покрытия, в 0.3.0 не включённый.

Основной оптимизатор L-BFGS-B имеет одинаковый бюджет 300 вычислений/60 итераций/600 s и две начальные точки. При отсутствии сошедшейся попытки применяются заранее предусмотренные резервные L-BFGS-B с eps=1e−5 и Powell: до 900 вычислений/180 итераций/600 s каждый, на тех же D-масках и границах. Поэтому 300 — бюджет основного поиска, а не общий максимум. Бюджет времени проверяется между вычислениями и не прерывает уже выполняющуюся линейную алгебру. Сохраняются wall/CPU времени модели; первичные вычисления имеют отдельные измерения времени, резервный поиск — собственную трассу и общее время. Запуск последовательный, BLAS=1, память ограничена конфигурацией и предварительной оценкой массивов.

## 4. Первый исполняемый блок: 73 кандидата

| Блок | Проверяемая гипотеза | Кандидаты | Что оценивается автоматически |
|---|---|---:|---|
| T0 | Простые эталоны | 2 | Ближайшая станция; IDW без высотной поправки, b и a_z |
| T1 | Постоянный, сезонный и месячный градиент | 3 | 1, 4 или 12 коэффициентов Δz, веса доноров |
| T2 | Суточная изменчивость вертикальной связи | 1 | 5 коэффициентов: z, z sin/cos года, z sin/cos местного среднего солнечного часа; ridge и веса |
| T3 | Нелинейная зависимость по высоте | 1 | Линейный spline с одним непрерывно оптимизируемым узлом, 2 коэффициента, ridge и веса |
| T4 | Локальный градиент текущего часа | 1 | Общий градиент, усадка донорского наклона к нему, веса |
| T5 | Пространственная интерполяция остатков фона | 1 | Фон country×month + 5 высотных годовых/суточных признаков на D, ridge и веса |
| P0 | Эталоны давления | 2 | Ближайшая станция; линейная поправка по высоте с весами |
| P1 | Гидростатический перенос | 2 | Веса; без или с остаточной высотной регрессией |
| H0–H4 | Выбор влагопеременной и доступность доноров | 60 | RH, ln(e), q, Td и T−Td × joint/own × 6 структур регрессии |

T2 использует среднее солнечное время UTC+longitude/15, без перехода на летнее время; это не истинное солнечное время с уравнением времени. В признаке суточной высоты учитываются долготы и цели, и доноров.

T3: \(f(z)=\beta_1z+\beta_2\max(z-h,0)\). Переносной признак равен \(f(z_i)-\sum_jw_jf(z_j)\); узел h ограничен квантилями 0.2–0.8 высот **D**, без значений V/C. Это глобальный spline, не модель конкретной инверсии в долине.

T4: \(g_t=(C_t+\lambda\gamma)/(V_t+\lambda)\), где C и V — взвешенные ковариация донорской T с высотой и дисперсия высоты. \(\hat T_i=\bar T+g_t(z_i-\bar z)\). γ оценивается линейно при заданной λ и весах. Наблюдение целевой T в локальный наклон не входит.

T5: сначала по абсолютным D-наблюдениям обучается \(B(c,m,z,\tau)\), затем \(\hat T_i=B_i+\sum w_j(T_j-B_j)\). При одновременных донорах одной страны country×month слагаемые сокращаются в переносе, но участвуют в оценке фоновых высотных коэффициентов. Это проверка способа оценки фона, а не независимый сеточный фон. DEM, экспозиция, холодные котловины и реанализ в первом численном блоке отсутствуют.

P1 переносит **станционное** давление, не давление на уровне моря:

\[
\widehat p_{j\to i}=p_j\exp\left[-\frac{g(z_i-z_j)}{R_d\bar T_{v,j}}\right],
\quad \bar T_{v,j}=\frac{T_j+\hat T_i+546.3}{2}(1+0.61q_j).
\]

Здесь высоты в m, T в °C до перевода в K, \(R_d=287.05\), g=9.80665; q_j — удельная влажность донора, предполагаемая постоянной в коротком вертикальном слое. Целевая T предсказана, целевая RH или p в перенос не подставляются. Используются совместимые доноры T/RH/p; контрольная маска P включает наблюдаемое p, готовые физические доноры и прогноз T, но не требует наблюдаемой целевой RH. Постоянный градиент p — эмпирический эталон, не универсальная барометрическая формула.

## 5. Влажность: честное сравнение координат и покрытия

\[
e=\frac{RH}{100}e_s(T),\qquad q=\frac{\epsilon e}{p-(1-\epsilon)e},\qquad
e=\frac{qp}{\epsilon+(1-\epsilon)q},\quad \epsilon=0.621945.
\]

\(e_s\) — Buck над жидкой водой; эта фаза сохраняется и при T<0 °C. Td получается численной инверсией той же формулы в [−80,50] °C. Невозможная инверсия обозначается пропуском. D=T−Td — **дефицит точки росы**, буква D в названии координаты не меняет обозначение обучающей части. q — kg водяного пара/kg влажного воздуха, не влагосодержание на kg сухого воздуха. Абсолютная влажность в g/m³ и прямая e без логарифма не входят в эту первую матрицу; их можно зарегистрировать как отдельное расширение.

Шесть структур для каждой координаты: height-IDW-OLS, seasonal-height-IDW-OLS, monthly-height-IDW-OLS, harmonic-height-IDW-ridge, height/east/north-Gaussian-OLS, seasonal-height/east/north-Gaussian-Huber. Коэффициенты и веса **вновь оцениваются отдельно** для joint и own; простая смена доноров у старой регрессии не считается достаточным тестом.

| Координата | Что требуется у донора в own | Как восстанавливается RH |
|---|---|---|
| RH | RH | Прямой прогноз |
| ln(e) | T, RH, e>0 | 100 exp(ln(e))/es(предсказанной T) |
| q | T, RH, p, 0<e<p | Сначала e(q, предсказанное p), затем RH с предсказанной T |
| Td | T, RH, допустимая Td | 100 es(предсказанной Td)/es(предсказанной T) |
| T−Td | T, RH, допустимая Td | Сначала Td=предсказанная T−предсказанный дефицит, затем RH |

В joint все координаты используют одних и тех же допустимых T/RH/p доноров с допустимой инверсией Td. Последнее условие применяется ко всем пяти координатам, чтобы домен Td не изменял только её донорский набор. Для общих контрольных часов дополнительно нужны T/RH/p цели, допустимая Td и общие прогнозы T/p. Число часов фиксируется **до** оценки кандидатов. В имеющемся пилоте это ожидаемые 6672 случая, но программа вычисляет и сохраняет фактическое число.

Для own отдельно выводится способность построить прогноз на календарной сетке и ошибка при наличии наблюдаемой **RH**. Не следует требовать наблюдаемую целевую p для оценки восстановленной RH через q: в прогнозе p уже предсказана. Производные e/q/Td оцениваются на собственных допустимых референсах, поэтому их числа наблюдений могут различаться. Нельзя сравнивать own MAE при разных часах как доказательство превосходства: основной критерий остаётся общей маской.

Общие T/p в основном блоке H заморожены по D-контрольным точкам предыдущей версии. В каждом внутреннем исключении семейства были исключены и из обучения, и из настройки этих вспомогательных моделей. Контрольные точки D+V не используются. Это изолирует влагопеременную и доноров от изменения вспомогательных моделей. Затем проводится отдельная диагностика: замена T, p и обеих на новые выбранные прогнозы без перенастройки влажности. Она не считается оптимизированной совместной цепочкой. Анализы с истинными T/p/e/q допускаются только как подписанные диагностические «оракулы», не как исполнимые прогнозы для новой точки.

RH<0, RH>100, e>=p, q вне [0,1) считаются и сохраняются; обрезка отсутствует. Обратное преобразование может дать пересыщение, это самостоятельный результат. Ограничение насыщением следует впоследствии сравнить отдельным кандидатом с теми же часами, а не скрывать им ошибку исходной модели.

## 6. Метрики и решения после первого запуска

Для каждого кандидата сохраняются MAE, RMSE, bias, macro MAE, покрытие, ошибки по странам/станциям/месяцам, QC-страты, физические нарушения, интервалы местного часа, высоты цели и расстояния до ближайшего допустимого донора. Для последних интервалов расстояние относится к допустимости доноров конкретной модели: joint/own расстояния могут различаться. Разница ошибок по этим группам является описательной ассоциацией, а не причинным эффектом высоты или QC.

Сравниваются температурный победитель и height-эталон, а также own против joint для каждой влагопеременной на общих случаях. Условный bootstrap 2000 раз выбирает станции с возвращением отдельно внутри стран; все часы станции переносятся вместе. Это исследовательский интервал после отбора на V, при фиксированном годе/календаре; он не учитывает весь процесс выбора моделей и не доказывает значимость на независимых годах. Нельзя считать сотни коррелированных часов сотнями независимых станций.

Кандидат может стать ELIGIBLE только при сходимости, полном прогнозе на фиксированной маске, минимальном числе случаев и представленных странах. ELIGIBLE означает техническую пригодность к сравнению, не достаточную точность для зданий. Попавшие на границу параметры, слабое высотное покрытие и неудачные оптимизации обсуждаются. Если лучшая модель ошибается в отдельном зимнем бассейне, глобальная средняя не закрывает этот дефект.

После V выбираются экономные структуры с проверкой практической разницы, месячных смещений и покрытия. При численной ничьей используется меньше коэффициентов, затем стабильный ID; смысловая близость результатов не сводится к округлённому «победителю». Для следующей независимой оценки заранее фиксируются итоговая цепочка, правила доноров, QC и гипотезы. Необходима проверка на новых семействах и временных блоках; закрытая C открывается отдельным осознанным этапом после заморозки, вне этого кода.

| S: солнце | Ближайшая/IDW GHI; интерполяция индекса ясности/clear-sky; спутник или реанализ + остатки | GHI и временной интервал накопления, солнечная геометрия, высота, ясное небо, горизонт | Дневные MAE/RMSE и bias, месячная энергия, высота Солнца, облачность; ночь отдельно |
| S2: компоненты | Интерполяция измеренных DNI/DHI при наличии; затем модели разложения GHI | Независимые измеренные компоненты; общий GHI для сравнения decomposition | GHI=DHI+DNI cos(зенита), низкое Солнце, отрицательные компоненты; физическое замыкание не заменяет внешнюю точность |
| R: осадки | Ближайшая/IDW; двухчастная модель события и положительного количества; фон нормы × аномалия | Почасовые накопления/сдвиги интервалов, разрешение прибора, орография, фаза | Brier и reliability события, POD/FAR/CSI при заранее заданном пороге, MAE количества, bias сумм, сильные события |
| W: ветер | Скалярная скорость; векторные u/v; стандартизация высоты/шероховатости; рельефная поправка | Скорость, направление, высота/экспозиция прибора, шероховатость, препятствия | Ошибка скорости и вектора, направление только выше заранее заданного порога штиля, распределения/квантили |
| L: длинноволновое | Измеренный фон/IDW; физические модели по T/e/облачности | Независимая L↓, облачность, T/e, горизонт | Почасовой bias/RMSE, ясные/облачные ночи, зимние режимы |
| N: снег | Пространственные суммы/аномалии; баланс накопления и таяния | Высота/эквивалент снега, фаза осадков, T, облучение | События, сезонные максимумы, даты схода, сохранение массы |
| J: совместная цепочка | Отдельные модели против совместного подбора/физических ограничений | Замороженные лучшие T/H/p/S/R/W/L, внутренние cross-fit прогнозы | Ошибка компонентов и совместные экстремумы, физические связи, покрытие и стоимость |
| B: строительная значимость | Энергетические расчёты с наблюдаемым и восстановленным климатом | Замороженные здания/системы, одинаковый расчётный движок | Отопление/охлаждение, пик, скрытая нагрузка, комфорт, чувствительность к ошибкам каждой величины |

Эти строки — зарегистрированные задачи и требования, а не уже реализованные методы. Загруженный численный куб содержит только T/RH/p и производную ln(e); остальные этапы имеют BLOCKED_INPUT_NOT_IN_CUBE. Нельзя запустить их на пустых столбцах или объявить выполненными по тестам конвертации.

Для осадков и солнца сначала проверяются часовые метки: начало/конец накопления и UTC. Для разных сетей нужны эквивалентные измерительные операторы; не смешиваются станционное и приведённое давление, порыв и средний ветер, GHI и накопленная энергия. Гиперпараметры длины корреляции, числа соседей, степени IDW, орографических признаков и регуляризации оцениваются внутри D. Порог события задаётся исходя из разрешения измерений и цели до просмотра C, затем проверяется чувствительность.

## 8. Почему именно эти контрольные методы

Meteonorm 8.2 служит инженерным референсом цепочки «месячная климатология → генерация суток/часов». В документации описаны модифицированная Shepard-интерполяция, поправки на высоту/локальные условия и работа с Td. Это не эталон синхронной реконструкции конкретного наблюдённого часа. Его константы не переносятся автоматически на новую сеть. Современная документация Meteonorm после версии 8 не считается описанием установленного 8.2.

HYRAS v6 — референс региональных нелинейных высотных профилей и интерполяции Td с последующим RH; PRISM — учёта физиографии, а не только евклидова расстояния; Frei — нелинейных профилей/неевклидовой геометрии в швейцарском рельефе. Эти работы мотивируют будущие признаки, но простой spline или донорский наклон не называются их воспроизведением. Суточные или месячные ошибки опубликованных работ нельзя напрямую сравнить с почасовой MAE этого пилота.

ERA5-Land показывает другой физически мотивированный выбор: коррекция q с сохранением RH при поправке высоты. Следовательно, «q всегда сохраняется при переносе» не является универсальным законом. Нужен прямой эксперимент с конечной RH и вспомогательной T. Для осадков полезен пример RhiresD с климатическим фоном и относительной аномалией; для ветра WAsP отделяет общий климат от локальных воздействий шероховатости/орографии. Для солнечного блока референс PVGIS включает спутниковые/реанализные поля и горизонт.

Первичные источники для теоретического обоснования:

- Meteonorm 8.2, Theory, July 2023, главы пространственной интерполяции и генерации, предоставленный пользователем `mn82_theory.pdf`.
- DWD HYRAS-DE-HURS v6: https://opendata.dwd.de/climate_environment/CDC/grids_germany/daily/hyras_de/humidity/DESCRIPTION_HYRAS-DE-HURS_V6_en.pdf
- Frei, 2014, *Interpolation of temperature in a mountainous region using nonlinear profiles and non-Euclidean distances*, DOI: https://doi.org/10.1002/joc.3786
- Daly et al., 2008, PRISM: https://prism.oregonstate.edu/pubs/link/2008_daly-etal_ijoc.pdf
- Muñoz-Sabater et al., 2021, ERA5-Land: https://doi.org/10.5194/essd-13-4349-2021
- MeteoSwiss RhiresD, суточные осадки, описание продукта: https://www.meteoswiss.admin.ch/services-and-publications/service/weather-and-climate-products/climate-spatial-analyses.html
- CHELSA, Karger et al., 2017: https://pmc.ncbi.nlm.nih.gov/articles/PMC5584396/
- JRC PVGIS, Data sources and calculation methods: https://joint-research-centre.ec.europa.eu/photovoltaic-geographical-information-system-pvgis/general-information/data-sources-calculation-methods_en
- DTU, Wind Atlas Methodology: https://wasp.dtu.dk/software/wasp/wind-atlas-generation/wind-atlas-methodology

## 9. Запуск и результаты для проверки

Новый код распаковывается в существующую папку расчётных программ, рядом с `ige_humidity.py`. `config_auto_regression.json` не изменяется. Нужны установленные numpy/scipy из `requirements_regression.txt`; новый BAT не скачивает зависимости. По умолчанию он использует завершённую папку `humidity_results/20261108T194858_552399Z_abe8e77a`. Можно явно указать другой проверенный источник 0.2.1.

```text
python ige_next_experiments.py run --config config_interpolation_v030.json
python ige_next_experiments.py run --config config_interpolation_v030.json --source-run "humidity_results/имя_запуска"
python ige_next_experiments.py resume --run "interpolation_experiments/имя_запуска"
```

При остановке завершённые кандидаты не пересчитываются, их хеши проверяются. Ошибочный кандидат не исчезает после перезапуска; изменение бюджета или метода требует нового запуска и новой спецификации. Итоги: `REPORT_RU.md`, `summary.json`, `comparison.csv`, `coupling_diagnostic.json`, `models/.../result.sealed.json`, трассы и прогнозы. Код завершения 0 означает завершённую техническую матрицу; код 2 — ошибку входа или незавершённые кандидаты. Этот код не является оценкой научной точности.
