# IGE — локальный аудит E0 и малый инженерный пилот E1.0

Версия 0.1.0, 2026-11-07. Python 3.10+, только стандартная библиотека.
Поддерживаются исходные структуры наших загрузчиков GeoSphere AT, DWD DE и
MeteoSwiss CH. Интернет для расчёта не нужен.

## Размещение

Распакуйте содержимое пакета в папку **ClimateExperiments рядом с Database**.

| Путь относительно общего корня | Что лежит внутри |
|---|---|
| `Database/AT` | Австрийский загрузчик и его скачанные данные |
| `Database/DE` | Немецкий загрузчик и его скачанные/поступающие данные |
| `Database/CH` | Швейцарский загрузчик и его скачанные/поступающие данные |
| `ClimateExperiments/ige_experiments.py` | Точка входа расчётов |
| `ClimateExperiments/config_E0_E10.json` | Окна, методы, число процессов и относительные пути |
| `ClimateExperiments/results` | Отчёты, фиксированные снимки, прогнозы и рабочий кэш |

Например, если данные лежат в `E:\Climate\Database`, код должен лежать в
`E:\Climate\ClimateExperiments`. Пробелы и кириллица в пути допустимы. Пути
в конфигурации считаются **относительно файла конфигурации**, независимо от cwd.

Внутри каждой страны программа рекурсивно ищет `plan.json` реального download-run
с каталогом `receipts`. Дополнительные уровни вроде `Database/AT/AT/downloaded/...`
допустимы. Переносить исходные папки или экспортировать годовые CSV не требуется.
Изолированные годовые CSV без исходного плана/receipts не объявляются проверенным
источником. Сохраните полную структуру результатов загрузчика.

## Запуск

Двойной щелчок по **RUN_E0_E10.bat** запускает аудит, затем пилот. В консоли
показывается прогресс. BAT не скачивает Python и не устанавливает пакеты.

Либо из терминала в папке ClimateExperiments:

```bat
python ige_experiments.py run --config config_E0_E10.json
```

Каждый запуск создаёт новый `results/<UTC-время_ID>`. Главные файлы:

| Файл внутри результата | Содержание |
|---|---|
| `REPORT_RU.md` | Короткий общий отчёт и ссылки на этапы |
| `summary.json` | Машинная сводка и признаки незавершённых проверок |
| `E0/REPORT_RU.md`, `E0/summary.json` | Файловая целостность и состояние передач |
| `E0/jobs.csv` | Проверенные, ожидаемые и помещённые в карантин запросы; причины |
| `E0/receipt_coverage.csv` | Сводки наличия величин и QC, сохранённые загрузчиками |
| `E0/snapshot.json` | Зафиксированные источники, хеши и доступные завершённые jobs |
| `E10/selection.sealed.json` | Выбранные по метаданным цели, пулы доноров и часы |
| `E10/availability.csv` | Наличие T/RH/p в выбранных окнах; категории QC |
| `E10/dataset.sealed.json.gz` | Точные значения/пропуски, операторы и происхождение подвыборки |
| `E10/run_specification.sealed.json` | Методы, параметры, ожидаемые jobs и хеши кода |
| `E10/workers_1/metrics.csv`, `E10/workers_2/metrics.csv` | Ошибки и собственное покрытие каждого метода |
| `E10/workers_N/paired.csv` | Ошибки кандидата и NN на общих часах |
| `E10/workers_N/qc_metrics.csv` | Отдельные категории QC контроля |
| `E10/workers_N/<job_id>/predictions.csv` | Каждый час, доноры, веса, QC доноров, прогноз, контроль и причина отказа |
| `E10/summary.json` | Профили времени/RSS и совпадение хешей прогнозов |

Код завершения **0** означает завершение инженерной операции, **2** — ошибку
источника/карантин, отсутствие оцениваемых случаев или незавершённый пилот.
Ожидаемые загрузки DE/CH сами по себе не считаются ошибкой.

Только аудит:

```bat
python ige_experiments.py audit --config config_E0_E10.json
```

Повторное чтение всех байтов без использования кэша хешей:

```bat
python ige_experiments.py run --config config_E0_E10.json --rehash
```

Самопроверка численных контролей без доступа к Database:

```bat
python ige_experiments.py self-check
```

Пилот можно отдельно запустить по `E0/snapshot.json` прежнего аудита с той же
конфигурацией через `pilot --snapshot <путь> --config config_E0_E10.json`.
Изменившаяся конфигурация требует нового аудита. Изменившийся исходный CSV или
его метаданные исключаются с причиной, а не подменяются незаметно.

## Что именно проверяется в E0

- Целостность плана, ID запроса и связь receipt с запросом.
- Наличие полного ожидаемого набора артефактов завершённого запроса.
- SHA-256 оригинальных архивов, сохранённых CSV и метаданных, заголовки CSV.
- Реестры станций/семейств и опубликованная геометрия; непроверенные исторические
  высоты приборов остаются явно обозначенными proxy.
- Сводки доступности/QC **из receipts**. Это не повторное вычисление объединённой
  почасовой полноты всего десятилетия. Планы с перекрытием не суммируются как
  независимые наблюдения. Точные почасовые маски строятся для подвыборки E1.0.

При повторном запуске хеш можно взять из собственного SQLite-кэша только при
совпадении размера, mtime, ctime и идентификатора файла с прежней проверкой.
Отчёт различает свежую проверку и `CACHED_HASH_UNCHANGED_STAT`. Для независимо
повторённой проверки каждого байта используйте `--rehash`.

SHA сохранённого сжатого raw проверяется заново. Исторический статус проверки
поставщиком/хеша **распакованного** оригинала наследуется из загрузчика и не
выдаётся за повторную независимую проверку исходного провайдера.

Исходники открываются только на чтение. В Database не создаются файлы блокировок,
кэш, исправления и результаты. Программа не ждёт downloader lock: берёт только
завершённые подтверждённые jobs, обнаруженные при их обработке. Поступившие позже
данные участвуют в следующем снимке. Одновременная запись или повреждение уже
подтверждённого файла приводит к явной ошибке/карантину.

## Малый пилот по умолчанию

**Роль: D_DEVELOPMENT.** Четыре непрерывных 48-часовых окна 2025 года: 1–2 февраля,
1–2 мая, 1–2 августа и 1–2 ноября. Это 192 ожидаемые часовые позиции на цель.
До трёх целей на страну выбираются по квантилям опубликованной высоты среди
доступных частей; значения и ошибки не используются для выбора.

Это конкретный малый инженерный дизайн, а не подтверждающая выборка 36 целей
из иллюстративного расчёта ресурсов программы v1. Точные часы сохраняются до
scoring. Менять окна можно в конфигурации до нового запуска; предыдущий результат
остаётся отдельным, включая отказы и неудачные варианты.

На каждый час и величину отдельно выбираются доступные совместимые доноры из
фиксированного пула: до 20 кандидатов, 100 km, перепад высоты до 1500 m.
Цель, её семейство и почти совпадающие площадки до 0,1 km исключаются.
Среди доноров одно семейство не учитывается дважды. Страны не смешиваются:
совпадение UTC-метки не доказывает одинаковый оператор наблюдения.

Методы:

- **NN_NATIVE:** ближайший доступный независимый донор.
- **IDW_NATIVE:** веса `1 / max(d_km, 0.25)^2`, от 2 до 4 доступных доноров.
- **IDW_T_FIXED_LAPSE_PROXY:** те же веса и поправка
  `T_target_from_donor = T_donor - 0.0065 * (z_target - z_donor)`.
  Применяется только к T; используется опубликованная высота станции как proxy.

Влажность здесь переносится как сырой скалярный контроль. Это не физически
согласованное состояние E1.H. Давление переносится как сырой контроль без
гидростатической поправки; это не pressure-квалификация E2. Никакого fit нет.

Сначала выполняется профиль с одним worker, затем те же jobs с двумя процессами
через spawn. Прогнозы должны совпасть побайтово. На таком малом наборе два процесса
могут оказаться медленнее из-за запуска процессов — это допустимый измеренный
результат. Измеряются подготовка, wall time и peak RSS каждого процесса; максимум
одного worker не называется суммарной памятью компьютера. Число процессов можно
изменить в `benchmark_workers`; без двух разных профилей сравнение не заявляется.

В отчёте отдельно показаны ошибки на общих часах, собственное покрытие, число
контролей, прогнозы без контроля и все отказы. Нулевой знаменатель даёт null.
Ошибки выполнения сохраняют запланированные знаменатели и не исчезают из отчёта.
Малый пилот не вычисляет доверительные интервалы и не выбирает научного победителя.

## QC, время и величины

| Источник | T | RH | Давление станции | QC |
|---|---|---|---|---|
| GeoSphere AT | `tl` | `rf` | `p` | Нативные `*_flag`; automatic и manual вместе в primary |
| DWD DE | `TT_TU` | `RF_TU` | **`P0`** | Нативные QN сохраняются как отдельные категории |
| MeteoSwiss CH, SMN | `tre200h0` | `ure200h0` | `prestah0` | `not_supplied`, ручной/автоматический статус не выдумывается |

Для AT `10/11/12` и `20/21/22` участвуют в primary; `0` и неопределённые коды —
в `sensitivity_all_published`. Это не доказательство неверности непроверенных
наблюдений. Original/changed/unknown остаются отдельными категориями.
QC контроля и доноров записываются раздельно. `rejected_native_qc` по умолчанию
пуст: явные reject-правила можно задать точными нативными строками на основании
документации; меньший номер QN не объявляется автоматически браком.

В DWD **`P` — давление на уровне моря, `P0` — на уровне станции**. Если Einheit
в датированной строке P0 пустая, hPa берётся из явного описания продукта v24.03,
а не угадывается по величине числа. Иное непустое обозначение единицы не
переопределяется; несовпадающее описание reference блокирует P0.
Основание: [DWD hourly pressure v24.03, таблица полей](https://opendata.dwd.de/climate_environment/CDC/observations_germany/climate/hourly/pressure/DESCRIPTION_obsgermany_climate_hourly_pressure_en.pdf).
Хеш ранее полученной PDF и неизменяемый источник приведены в SOURCE_ANCHORS.json.

Сохраняются UTC, нативный параметр, источник единиц и оператор. DE требует
датированную запись параметра; неизвестная/неоднозначная запись не превращается
в подтверждённую. CH до 2018 получает свой legacy operator ID. Минутные метки,
неразрешённое время и неизвестные операторы не сдвигаются/не округляются молча.
Пилот не проверяет ветер, солнечные компоненты или precipitation-модель; их файлы
участвуют в файловом E0-аудите и сохраняют собственные сводки.

## Границы результата

E0 и скалярная инженерная часть E1.0 реализованы. **Полный E1.0 ещё не закрыт:**
replay принятых P8.2F / S1 / R1 требует их точных входов, месячных/годовых контрактов
и отдельных адаптеров. В каждом отчёте эти строки имеют SOURCE_BLOCKED либо
CAPABILITY_BLOCKED. Новые почасовые контроли не называются прежними методами.

Ваш полный AT-массив находится на вашем компьютере; проверка небольших сохранённых
примеров при разработке не является аудитом этого массива. Нет новых утверждений
о независимой точности, новой квалификации IV1, будущем климате или энергии здания.
Чтение контейнера регистрируется: находящиеся в нём другие периоды не следует
объявлять нетронутым старым holdout. Прежние правила IV1 не изменены.

Повторный запуск после поступления DE/CH создаст новый снимок и может выбрать
другие metadata-цели. Такие запуски нельзя незаметно объединять в одну проверку
методов: сравнивайте зафиксированные selection/source IDs.

Для последующего разбора достаточно начать с `summary.json`, `E0/jobs.csv`,
`E10/summary.json` и `E10/workers_1/metrics.csv`. Они небольшие; пересылать всю
Database для первичной оценки не требуется.

## Проверка пакета

```bat
python -m unittest discover -s tests -v
```

Тесты проверяют численные оракулы, реальные малые CSV, пропуски, QC, исключение
семейства цели, временные операторы, неоднозначные перекрытия, повреждения/гонки
входов, сохранение знаменателей, пути с пробелами/кириллицей и spawn-параллелизм.
Синтетические fixtures явно отделены от небольших реальных примеров.
