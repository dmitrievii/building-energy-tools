# IGE — автоматический подбор пространственных регрессий v0.1.1

Программа обучает пространственные поправки на почасовых наблюдениях AT/DE/CH,
настраивает параметры весов и выбирает структуру по отдельной проверочной выборке.
Это следующий этап после E0/E1.0. Он не меняет прежние фиксированные контроли.

Обновление 0.1.1 улучшает диагностику путей JSON. Для проверки без расчёта и без
NumPy/SciPy: `python ige_regression.py check-config --config config_auto_regression.json`.
BAT выполняет эту проверку до установки зависимостей. Инструкция:
[WINDOWS_PATHS_RU.md](WINDOWS_PATHS_RU.md). Расчётные методы сохранены.

## Запуск на Windows

1. Распакуйте пакет в **ClimateExperiments**, рядом с **Database**, внутри которой
   лежат **AT**, **DE**, **CH**. Сохраняйте `plan.json`, `receipts`, `raw`, `csv`/`parts`
   и метаданные загрузчиков. Экспорт годовых CSV не требуется.
2. Откройте `config_auto_regression.json`. Строка `"database": "../Database"`
   подходит для этой структуры. Если ваши страны по-прежнему находятся в
   `E:\User Folder\Documents\00_TU Graz\Dissertation\IGE\Climate\AT`, используйте:

   ```json
   "database": "E:/User Folder/Documents/00_TU Graz/Dissertation/IGE/Climate/AT"
   ```

   Это общий каталог, содержащий папки стран. Пути считаются от файла конфигурации.
3. Запустите **RUN_AUTO_REGRESSION.bat**. Нужен установленный Python 3.10+.
   BAT создаёт отдельное окружение `.venv_regression`, устанавливает зависимости
   и запускает расчёт. Интернет нужен при установке NumPy/SciPy; сами наблюдения
   читаются с диска. Python BAT не устанавливает.

Командный запуск:

```bat
python -m pip install -r requirements_regression.txt
python ige_regression.py self-check
python ige_regression.py run --config config_auto_regression.json
```

Если использовали BAT, его Python находится в `.venv_regression\Scripts\python.exe`:

```bat
.venv_regression\Scripts\python.exe ige_regression.py self-check
```

В `regression_results/<время_ID>` появятся отчёт и результаты. Код **0** означает
завершённый запрошенный fit, **2** — незавершённую область данных, ошибку источника,
отсутствие подходящей модели или отказ вычислений. Даже при коде 2 пригодные
результаты остальных величин сохраняются. Программа не ждёт завершения DE/CH:
завершённые части входят в снимок, ожидаемые части остаются в E0-реестре.

Первый E0 проверяет SHA-256 исходных артефактов и может занимать заметное время
на большой базе. Следующие запуски используют собственный кэш неизменившихся
файлов. `--rehash` снова читает все байты. Database открывается только для чтения.

## Что программа оценивает

Для каждого допустимого часа отдельно строится перенос

\[
\widehat y_{s,t}=\sum_i w_{si,t}(\eta)y_{i,t}+X_{s,t}(\eta)\theta.
\]

Первый высотный признак — `z_target − Σ(w z_donor)` в **km**, а не регрессия
абсолютной температуры на высоту. Синхронный фон доноров вычитается до fit.
Свободного члена нет: постоянный пространственный признак сокращается в контрасте.

Линейные коэффициенты θ находятся через SVD (`numpy.linalg.lstsq`). При
фиксированных весах это обычная линейная задача для OLS/ridge; Huber решается
итеративным взвешенным LS с проверкой сходимости. Проверяются поддержка каждого
признака, ранг и обусловленность до регуляризации. Ridge не легализует
неидентифицируемый высотный/географический тренд.

Параметры η находятся **непрерывной ограниченной оптимизацией L-BFGS-B** по
внутренним групповым проверкам D. Производная оценивается численно. Это локальный
поиск с двумя объявленными начальными состояниями, а не декартова сетка коэффициентов.
Сходимость не доказывает глобального оптимума или физической уникальности.

| Кандидат по умолчанию | Линейный базис | Пространственные веса | Регрессия |
|---|---|---|---|
| `height_idw_ols` | Один общий высотный коэффициент | IDW | OLS |
| `seasonal_idw_ols` | Четыре сезонных высотных коэффициента | IDW | OLS |
| `monthly_idw_ols` | Двенадцать месячных высотных коэффициентов | IDW | OLS |
| `harmonic_idw_ridge` | Высота × {1, sin(год), cos(год)} | IDW | Ridge |
| `geo_gaussian_ols` | Высота, восточный и северный контрасты | Gaussian | OLS |
| `seasonal_geo_gaussian_huber` | Сезонная высота, восток, север | Gaussian | Huber |

Это зарегистрированные комбинированные кандидаты. Их сравнение не изолирует
отдельный эффект ядра или робастной потери; для такого эксперимента нужно заранее
добавить соответствующие парные структуры в конфигурацию. Допустимы 1–20 кандидатов.
Конфигурация поддерживает указанные шесть базисов с каждым ядром/типом регрессии.

Все сравниваются для **T**, **RH**, станционного **p** и явно производного
**log_e_water**. Коэффициенты общие для участвующих стран; доноры одного переноса
берутся из той же страны и с точно совпадающим оператором наблюдения.
Региональная иерархия, ветер, осадки, солнечная радиация, кригинг, инверсии и
физически согласованный совместный T/p/RH fit в эту версию не входят.

`log_e_water = ln(RH × Buck_water(T) / 100 / 1 hPa)` использует явно заявленную
формулу насыщения над жидкой водой, включая отрицательные температуры. Требуются
допустимые T и RH и положительное e. Это **не независимо измеренное e**, не
проверка ледяной фазы и не подтверждение конечной точности совместного RH.
Оба входных источника и QC сохраняются в книге происхождения кэша.

Давление DE — **P0**, не приведённое к морю P. Высота площадки — опубликованный
proxy: эмпирический p-коэффициент не называется проверенной барометрической
высотой или квалифицированной гипсометрической моделью. Географические контрасты
рассчитываются локальной равноугольной аппроксимацией, расстояния — по сфере.

## Какие пространственные параметры подбираются

В метрике `r² = d_horizontal² + (a_z Δz_km)²` горизонтальный множитель фиксирован
равным 1. Обучаются относительный вертикальный множитель `a_z` и:

- для IDW — степень β, `w ∝ r^(−β)`, β в [0.1, 8];
- для Gaussian — ширина h, `w ∝ exp(−r²/(2h²))`; границы h определяются только
  геометрией обучающих D-доноров: от max(0.01 km, median(d)/20) до max(2 km, 10 max(d));
- log(a_z) в [−6, 7]; для ridge дополнительно log(λ) в [−14, 4].

Общий масштаб h в нормированном чистом IDW сократился бы; такого фиктивного
параметра здесь нет. Все совместимые доступные доноры выбранного пула получают
плавные веса. Фиксированного k или радиуса 100 km в обучаемых кандидатах нет.
Для регрессии/прогноза требуется минимум два независимых семейства. Ближайший
донор NN имеет собственное покрытие и может работать с одним семейством.
`n_eff = 1/Σw²` характеризует концентрацию весов, а не независимый размер выборки.

Старый градиент **−6.5 K/km**, горизонтальный IDW **β=2** и NN остаются строками
контроля. Они не становятся обучаемым победителем, prior, центром ridge или
единственным начальным состоянием. Полные старые P8.2F/S1/R1 replay сохраняют
собственные входные ограничения, но не блокируют новый fit.

## D, V, C и порядок расчёта

По умолчанию D = 2019–2021, V = 2023, C = 2025. Эти годы можно менять **до запуска**.
Объявляются разные календарные годы для каждой роли. Семейства площадок также
делятся на разные роли D/V/C с фиксированным seed и долями 60/20/20.
AT group и CH WIGOS объединяют физически связанные площадки; COMBINED не используется.
Почти совпадающие площадки до 0.1 km исключаются из доноров.

1. По метаданным выбираются до 24 семейств на страну через квантили высоты.
   Внутри семейств сохраняются все физические площадки. `sites_per_country: 0`
   включает все доступные семейства, но требует предварительной оценки памяти.
2. D делится на три fold по семействам. В каждой внутренней проверке проверяемые
   семейства отсутствуют **и в обучении, и в донорах** во всех периодах.
   Параметры весов и λ оптимизируются по внутренней ошибке D.
3. Все θ заново оцениваются на D. V-цели в V-годах получают только D-доноров.
   Структура выбирается по MAE с равным весом стран, затем станций. Численные
   совпадения в пределах `1e-10 × max(1, best_MAE)` разрешаются в пользу меньшего
   числа коэффициентов, затем OLS/ridge/Huber и ID. Это защита от округления,
   не статистическая проверка равенства точности.
4. По умолчанию θ выбранной структуры дообучаются на объединении случаев
   D-станции/D-годы и V-станции/V-годы, с D+V-донорами; η уже заморожены.
   Возможен `final_refit: D_ONLY`.
5. C по умолчанию **не оценивается автоматически**. После просмотра D/V-результатов:

   ```bat
   python ige_regression.py evaluate --run "regression_results/<время_ID>"
   ```

   Или замените `python` на `.venv_regression\Scripts\python.exe`, если запускали BAT.
   Проверяются три разных панели: C-площадки/C-годы; C-площадки/D-годы;
   D-площадки/C-годы. Геометрия/операторы сохраняются, из доноров исключается
   семейство каждой цели. Никакого подбора по C нет.

При первом открытии C до scoring создаётся `C_OPENED.json`; повторное открытие
требует `--repeat` и регистрируется отдельно, в том числе после неудачного первого
вычисления. Это запрет случайного повторного просмотра в рамках одного run, а не
невозможность заново открыть уже виденные данные через новый run. Такие повторения
надо раскрывать в исследовании. После подбора по C его нельзя считать новой
независимой проверкой.

Данные уже скачаны, а нативные контейнеры автоматически читаются при подготовке.
Здесь гарантируется вычислительное исключение C из fit/selection; **слепой доступ
к raw не заявляется**. Если эти площадки/годы уже влияли на прошлые решения,
независимость подтверждающей выборки требует отдельного пересмотра дизайна.
Численные тесты сами по себе не дают научного допуска методам.

Обучение и настройка η минимизируют взвешенную MSE для OLS/ridge; Huber — свою
объявленную робастную потерю. Порог Huber находится только на fit-части D по MAD
остатков начального OLS и фиксируется внутри каждой внутренней проверки.
Статистические веса уравновешивают страны → станции → месяцы. Выбор структуры
по V использует MAE, поэтому эти две задачи намеренно имеют разные критерии.

## Неполнота, QC и ресурсы

Полные годы не требуются. Доступность строится **по часам и величинам**. Отсутствие
T не удаляет пригодный p. Для производного e совместная доступность T/RH обязательна.
Отсутствующее значение контроля не мешает прогнозу, если его оператор известен
и есть совместимые доноры. Неизвестный оператор не восстанавливается догадкой.
Единицы/временные операторы не округляются и не сдвигаются для улучшения ошибки.

Автоматические AT-флаги 10/11/12 и ручные 20/21/22 участвуют в primary.
Часы без проверки 0/undefined можно включить отдельным запуском
`qc_mode: sensitivity_all_published`. Они не называются неправильными.
QC не превращается в придуманные веса доверия. DWD QN и CH `not_supplied`
сохраняют собственные значения без выдуманного ручного/автоматического статуса.
RH не обрезается, физические выходы за диапазон 0–100% считаются отдельно.

Инженерный запуск по умолчанию использует 15–16 числа каждого месяца
(`sample_start_day: 15`, `sample_days_per_month: 2`) и максимум 12 000 случаев
на partition. Часы выбираются по квотам станции/месяца **до чтения ошибок и
проверки наличия**. Сохраняются полный календарный знаменатель, размер подвыборки,
N наблюдений, N прогнозов и отказы. Метрики этой подвыборки нельзя называть
метриками всех часов десятилетия. Месячное окно до 28 дней поддерживается, но
не должно выходить за февраль: start_day + sample_days ≤ 29.

По умолчанию 24 задачи: 6 моделей × 4 величины. `workers: 1` — последовательный
расчёт. `workers: 2` параллельно выполняет независимые задачи; каждая использует
один поток BLAS и читает неизменяемый mmap-кэш. Эти профили проверены на совпадение
результатов; ускорение на малой выборке не гарантируется. Cube и матрицы случаев
имеют предварительную проверку заявленного бюджета памяти; это оценка массивов,
а не принудительный системный лимит RSS. Временной бюджет проверяется между
итерациями/проверками, он не прерывает системный вызов SVD посреди выполнения.

`max_evaluations` ограничивает число вызовов целевой функции суммарно по стартам.
Пределы итераций/времени задаются в `optimizer`. Оптимум на границе помечается.
Если ни один старт не сошёлся, модель получает `UNRESOLVED_OPTIMIZATION` и не
выбирается. Успешный старт остаётся допустимым, если дополнительный диагностический
старт исчерпал бюджет; это видно в `runs`. Почти плоская цель и численный ранг
записываются отдельно. Увеличивать бюджет следует на D, сохраняя историю запусков.

Сначала рекомендуется стандартная малая конфигурация и анализ времени/памяти.
Расширяйте годы, станции и часы новым запуском с сохранённой конфигурацией.
Научный глобальный optimum этой процедурой не обещается. Отрицательные результаты
и отказ от сложной модели сохраняются наравне с удачными.

## Результаты и повторное использование кэша

| Файл/папка | Содержание |
|---|---|
| `E0/` | Аудит исходных jobs, pending/quarantine, хеши |
| `cube/split.sealed.json` | Семейства, роли, fold и часы, зафиксированные до анализа значений |
| `cube/metadata.json`, `*.npy` | Неизменяемый численный кэш, QC/операторы/источники, SHA-256 |
| `run_spec.sealed.json` | Конфигурация, исходный cube, хеши кода, Python/NumPy/SciPy |
| `REPORT_RU.md`, `summary.json` | Основной итог, пригодные величины, ограничения |
| `model_comparison.csv` | V-MAE/RMSE/bias на общем наборе часов и причины отказов |
| `coefficients.csv` | θ после D-fit и заявленного финального fit, единицы на km |
| `selected_models.sealed.json` | Выбранные формулы, θ, η, λ/Huber, SVD-диагностика и происхождение |
| `models/<величина>/<модель>/result.json` | Внутренние fold, коэффициенты/ошибки, собственное и парное покрытие, QC, страны/станции/месяцы |
| `models/.../optimization_trace.json` | Все вызовы непрерывной оптимизации и причины отказов |
| `models/.../V_predictions.csv` | Каждый выбранный час, ошибка/отказ, n_eff, QC цели и доноров |
| `holdout_evaluations/<время_ID>/` | Отдельные C-панели, прогнозы и метрики; только после evaluate |

CSV сохраняются в UTF-8 с BOM. По каждой величине сохраняются MAE, RMSE, bias,
pooled P95 абсолютной ошибки, station/country macro MAE и знаменатели покрытия.
Нулевое N даёт null, а не нулевую ошибку. Доверительные интервалы по зависимым
часам/станциям эта версия не рассчитывает. Подробные donor QC выгружаются как
набор присутствующих страт; массив QC и источников каждого донора доступен в cube.

Можно отдельно подготовить кэш или повторить обучение с новым бюджетом/моделями:

```bat
python ige_regression.py prepare --config config_auto_regression.json
python ige_regression.py fit --config config_auto_regression.json --cube "regression_results/<подготовка>/cube"
```

Изменение исходного выбора, лет, QC или split требует нового cube. Изменение
моделей/бюджета может использовать прежний cube. Каждый fit получает свой run;
прерванный поиск модели не возобновляется посреди итерации. Изменившиеся массивы,
seal-файлы или код блокируют C-evaluate. Это проверка целостности, не цифровая
подпись и не защита от сознательной перезаписи всей истории.

## Проверка программы

```bat
python -m pip install -r requirements_regression.txt
python -m unittest discover -s tests -v
```

Описание фактически выполненных тестов: `AUTO_VALIDATION_RU.md` и
`validation/automatic_regression.json`. Малые реальные AT/DE/CH fixtures проверяют
нативное чтение; известные пространственные поля и эталонные коэффициенты —
явно синтетические численные контроли. Ваша полная Database здесь не обучалась.
