# Проверка дополнения влажности 0.2.0

8 ноября 2026 года, локальная Linux-среда, Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0.

`python -m unittest discover -s tests -v`: **151 тест, OK**, 12.620 s. Это 127 прежних тестов ядра и 24 новых теста цепочек влажности. Проверены независимое соотношение масс q/x, обращение e/q с одинаковыми единицами давления, влияние предсказанных T/p, отсутствие обрезания, общая поддержка и собственное покрытие, исключение семейств и выбор доступной альтернативной площадки, отсутствие влияния целевых значений на прогноз, групповые вложенные разбиения, равные веса стран и станций, блокировка ранее открытой C, preflight без NumPy/SciPy, полный численный D/V расчёт, возобновление, обнаружение изменённых прогнозов и отдельная C-оценка **синтетического** набора без обучения на C.

`python ige_humidity.py self-check`: три проверки PASS — q/e, обращение Buck и сохранение RH выше 100%.

`python tests/validate_humidity.py`: все **18 из 18** комбинаций шести штатных структур и трёх координат завершились как `ELIGIBLE`. Это искусственное гладкое поле с 15 семействами и ограниченной выборкой. Подробности и контрольные суммы реализации сохранены в `HUMIDITY_ALL_STRUCTURES_SYNTHETIC.json`. Малое время этого прогона не является оценкой продолжительности расчёта пользовательской базы.

Общие модули `ige_auto` и `ige_local` в этом дополнении не изменены. Новая логика расположена в `ige_hum` и `ige_humidity.py`; собственные параметры и результаты отделены от исходного запуска. Численная база из старого архива с ранее зафиксированными ошибками не принята как исправленные наблюдения.

Реальный новый D/V расчёт должен быть выполнен пользователем на исправленной Windows Database. Реальная C при разработке не оценивалась. Ни одна новая цепочка влажности пока не названа победившей на реальных данных. E0 принят по отдельному пользовательскому отчёту, изложенному в `E0_ACCEPTANCE_20261108_RU.md`; локального повторного чтения всей Database разработчиком не было.

В workflow добавлены эти же проверки для Ubuntu/Windows и Python 3.10/3.13. Результат локального запуска не подменяет результат GitHub Actions; статус CI сообщается отдельно после публикации.
