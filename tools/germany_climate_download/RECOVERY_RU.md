# Догрузка незавершённых архивов DWD — 1.0.0

Дополнение к `germany_climate.py` версии 1.0.0. Python 3.10+, стандартная
библиотека; установка пакетов не требуется. Основной загрузчик и его проверки
размера, CRC, структуры строк и SHA-256 остаются прежними.

## Что произошло в запуске 4478 заданий

Исходный план:
`e13ab8aa5ab68b337ab6bcea1fffa2655f36ec3b021b429712e5c5c37e016377`.
По предоставленному журналу завершены 4431 задания, остались 47:

| Число | Ошибка | Действие |
|---:|---|---|
| 6 | DNS `getaddrinfo failed` или тайм-аут | Повторное получение незавершённых ZIP |
| 1 | `Truncated/misaligned product row`, влажность станции `03591` | Получить заново и полностью проверить архив; строки не пропускать |
| 40 | `ZIP size differs from frozen directory listing`, солнечная радиация | Зафиксировать свежие индексы DWD в отдельном дополнительном плане |

Обычный повтор исходного `download` может помочь при сетевых ошибках, но не
устраняет расхождение между старым планом и пересмотренным архивом поставщика.
Не редактируйте размер внутри исходного `plan.json`: это нарушит его хеш и
воспроизводимость. Не требуется удалять уже скачанные данные.

При проверке 8 ноября 2026 года свежий ZIP влажности `03591` успешно разобран
исходным загрузчиком: 87342 строки за выбранный период, CRC и структура пройдены.
Прежняя ошибка строки в этом свежем файле не воспроизвелась; причина ошибки в
пользовательском файле без его исследования не установлена.

В текущем индексе радиации изменились размеры 35 из 42 архивов полного плана;
часть размеров уже снова совпадает со старым планом. Эти числа описывают разные
моменты времени: 40 ошибок — из пользовательского запуска, 35 — из новой проверки.

## Запуск в вашей папке DE

1. Распакуйте `germany_recover.py` и эту инструкцию **рядом с существующим
   `germany_climate.py`**. В этой же папке остаются ваш `plan.json` и `downloaded`.
2. Дождитесь завершения других загрузчиков, работающих с этой же папкой.
3. Выполните:

```bat
python germany_recover.py --plan plan.json --out downloaded
```

Программа сначала проверяет хеши готовых файлов. На большом наборе это занимает
время; сообщения `Verifying original receipts` означают проверку диска.
Подтверждённые 4431 задания повторно не скачиваются. При обнаружении повреждённого
готового файла он не засчитывается как завершённый и попадает в список догрузки.

Для незавершённых заданий сохраняются текущие оригинальные HTML-индексы DWD,
создаётся новый план и отдельная папка внутри `downloaded`. Команда печатает её
путь как `New supplementary plan: ...`. К каждому новому заданию привязан ID
исходного задания. Станция, группа, имя ZIP, URL и выбранный период сохраняются;
обновляются только зафиксированные сведения об архиве в индексе DWD.

При новых сетевых ошибках повторите **ту же команду**. Она учитывает готовые
файлы исходного запуска и всех связанных дополнительных планов. Новые планы
создаются только для оставшихся незавершённых заданий. Если первоначальное имя
архива исчезло у DWD, программа остановится с явной ошибкой: другое имя не угадывается.

## Как понять, что догрузка завершена

Итоговый JSON должен содержать:

```json
{
  "planned_original_jobs": 4478,
  "resolved_original_jobs": 4478,
  "remaining_jobs": 0,
  "all_jobs_resolved": true
}
```

Если все прежние файлы подтвердились и вы не делали промежуточных запусков,
ожидаются `completed_in_original_run: 4431` и `completed_via_recovery: 47`.
Это ожидаемые значения, а не результат проверки ваших локальных файлов здесь.

Отчёты записываются по путям:

```text
downloaded/recovery_control/e13ab8aa5ab68b337ab6b/recovery_summary.json
downloaded/recovery_control/e13ab8aa5ab68b337ab6b/resolved_jobs.json
```

`resolved_jobs.json` связывает каждое закрытое исходное задание с фактическим
планом и заданием, содержащими подтверждённый файл. Сохраните дополнительные
папки вместе с первоначальной папкой загрузки.

Проверка без сетевых запросов:

```bat
python germany_recover.py --plan plan.json --out downloaded --status-only
```

Код завершения: `0` — все исходные задания закрыты; `1` — ещё есть незавершённые;
`2` — ошибка конфигурации, доступа или подготовки нового снимка.

## Значение исходного и дополнительного планов

Исходный план, его результаты и старый отчёт не переписываются. После догрузки
старый `germany_climate.py download --plan plan.json` всё ещё может показывать
незавершённые задания: свежие версии находятся в другом плане.
Для общей полноты используйте **`all_jobs_resolved`** из `germany_recover.py`.
`exact_original_frozen_run_complete` остаётся `false`, если хотя бы одно задание
было закрыто версией из дополнительного плана.

Результат является явно описанной совокупностью версий поставщика с разными
датами получения. Он не объявляется снимком состояния всего DWD на одну дату.
Полнота метеорологических значений, QC-допуск и пригодность для EPW этим
дополнением не оцениваются.

E0 обнаруживает обе папки по обычным `plan.json` и проверяет их нативные файлы.
В E0 число запланированных заданий включает дополнительные планы; старые
заменённые задания могут оставаться `PENDING`. Это не означает повторную потерю
догруженных данных. Уникальное закрытие исходных заданий показывает отчёт
догрузки. Готовые данные доступны последующему чтению в прежнем формате;
состав поддерживаемых величин E1.0 не расширяется этим дополнением.

Обычный `export` читает только указанный план. Для восстановленного задания
передавайте путь дополнительного `plan.json`, показанный программой; экспорт
не объединяет планы автоматически. План с незавершёнными заданиями, необходимыми
для выбранных станции, группы и года, по-прежнему блокирует такой экспорт.

## Проверки поставки

Новый набор проверяет догрузку только незавершённых заданий, неизменность
исходных файлов, повтор без сетевых запросов, частичную догрузку, сетевой сбой,
строгий контроль размера и строк, повреждение ZIP или индекса, неверную привязку
задания, блокировки и пути с кириллицей/пробелами. Полный запуск из исходной
поставки:

```bat
python -m unittest discover -s tests -v
```

Отдельная реальная проверка ограничена двумя заданиями: одно уже готово,
второе догружается из DWD. Это не проверка пользовательской базы из 4478 заданий.
Машиночитаемые результаты: `validation/recovery_20261108.json`.
