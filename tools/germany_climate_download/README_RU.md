# Немецкие почасовые наблюдения DWD: IGE Downloader 1.0.0

Отдельная программа для получения реальных станционных наблюдений **Deutscher
Wetterdienst, Climate Data Center (CDC)**, координат и метаданных. Python **3.10+**,
только стандартная библиотека. Установка пакетов через `pip` не требуется.

Результат — исходные наблюдения и проверяемая основа для последующего допуска
станций, интерполяции и валидации климатического генератора IGE. Самостоятельно
загрузчик не восстанавливает пропуски, не интерполирует климат и не создаёт EPW.

## Состав поставки

| Файл | Назначение |
|---|---|
| `germany_climate.py` | Обновление каталога, поиск соседей, планирование, загрузка, экспорт |
| `catalog/stations.csv` | Готовый читаемый CSV: DWD ID, название, широта, долгота, высота, группы |
| `catalog/stations.geojson` | Станции для карты; координаты `[longitude, latitude]` |
| `catalog/station_groups.csv.gz` | Периоды и координаты отдельно по группе и разделу DWD |
| `catalog/archives.csv.gz` | Полный перечень опубликованных ZIP, размеры, интервалы и источники |
| `catalog/catalog.json.gz` | Проверяемый каталог, используемый программой |
| `catalog/catalog_manifest.json` | Числа, источники, даты получения, SHA-256 и лицензия |
| `catalog/sources/` | Исходные списки, HTML-каталоги, официальные PDF и условия использования |
| `parameters.json` | Навигация по величинам, единицам и важным различиям |
| `config_smoke.json` | Небольшой запуск для одной станции и одних суток |
| `config_2016_2025.json` | План полного десятилетия 2016–2025 |
| `VALIDATION_RU.md`, `validation/` | Отчёт проверки и машиночитаемые результаты |
| `tests/` | Автономные проверки и производные образцы реальных ответов DWD |

`.gz` — обычный gzip. Программа читает его сама. Исходные ответы после распаковки
совпадают с полученными байтами; в манифесте есть хеши исходного и сохранённого
представления. Источники разных обновлений сохраняются под именами с хешем.

## Быстрый запуск

Откройте терминал в распакованной папке. В Windows вместо `python` можно
использовать `py -3`, в Linux/macOS — `python3`.

```bash
python germany_climate.py plan --config config_smoke.json --out plan_smoke.json
python germany_climate.py download --plan plan_smoke.json --out downloaded
python germany_climate.py export --plan plan_smoke.json --out downloaded --station-id 01048 --year 2025 --group pressure --plain-csv
```

Станция `01048` — Dresden-Klotzsche. В конфигурации выбраны **1 июня 2025 года**,
девять разделов `recent` и отдельный архив радиации `row`. Проверяется по одним
суткам данных; названия экспортированных файлов `2025.csv` не означают наличие
полного года. Период `recent` скользящий: для более позднего повторения нужно
обновить каталог и выбрать день, который ещё представлен в архиве, либо выбрать
`historical`. Нулевое число выбранных строк программа показывает явно.

`plan` скачивание наблюдений не запускает. В отличие от австрийского API,
DWD предоставляет **целые ZIP-архивы станции и группы**. Даже запрос одних суток
для радиации требует получить весь соответствующий многолетний ZIP; отбор
заданного периода выполняется при разборе. До запуска показывается размер ZIP
из зафиксированного каталога.

## Найти станции по координатам

Например, температура рядом с Берлином на заданную дату:

```bash
python germany_climate.py nearest --lat 52.52 --lon 13.405 --date 2025-01-01 --groups air_temperature --limit 10 --radius-km 100 --csv nearest_berlin.csv
```

Для наличия нескольких групп требуется каждая указанная группа:

```bash
python germany_climate.py nearest --lat 51.13 --lon 13.77 --date 2025-06-01 --groups air_temperature pressure wind --elevation-m 225 --max-height-difference-m 500 --exclude-ids 01048 --csv nearest_dresden.csv
```

Расстояние вычисляется по гаверсинусу с радиусом Земли 6371,0088 км. Географическая
близость, высотный фильтр и интервалы каталога формируют список кандидатов;
репрезентативность, полнота и независимость доноров ещё не допускаются.

**Важное отличие от каталога GeoSphere:** общий список DWD содержит последние
опубликованные координаты станции. У одного DWD ID может быть несколько площадок
в разные годы. Дата в `nearest` фильтрует опубликованный период ряда, но не делает
последние координаты историческими. Поэтому CSV явно содержит
`coordinate_role=latest_published_position_not_dated_history`, а результат поиска —
`donor_admission=not_assessed`. Если координаты между группами различаются,
`coordinate_variants` больше 1; выбран вариант с наиболее поздним периодом ряда.

Для использования координат в исторической интерполяции берите датированные
интервалы `geography_history` из сохранённого `metadata/<job_id>.json`. Они
прочитаны из оригинального `Metadaten_Geographie_*` внутри ZIP. Высота станции
не объявляется высотой барометра или другого прибора. `station_id` — ID DWD,
не WMO-номер и не доказательство независимости физических площадок.

## Поддерживаемые группы

| Группа в конфигурации | Основные оригинальные поля | Величины и единицы |
|---|---|---|
| `air_temperature` | `TT_TU`, `RF_TU` | Температура °C, относительная влажность % |
| `dew_point` | `TT`, `TD` | Температура и точка росы °C |
| `moisture` | `ABSF_STD`, `VP_STD`, `TF_STD`, `P_STD`, `TT_STD`, `RF_STD`, `TD_STD` | Влажностные величины и сопутствующие параметры; в том числе рассчитанные поставщиком |
| `pressure` | `P`, `P0` | Давление на уровне моря и на высоте станции, hPa |
| `wind` | `F`, `D` | Скорость m/s и направление °; оператор зависит от истории ряда |
| `precipitation` | `R1`, `RS_IND`, `WRTR` | Осадки mm и исходные коды |
| `cloudiness` | `V_N`, `V_N_I` | Общая облачность в восьмых долях и признак происхождения |
| `sun` | `SD_SO` | Продолжительность солнечного сияния, минуты |
| `solar` | `ATMO_LBERG`, `FD_LBERG`, `FG_LBERG`, `SD_LBERG`, `ZENIT`, `MESS_DATUM_WOZ` | Длинноволновая, диффузная и глобальная радиация J/cm², сияние min, зенит °, вторичная шкала WOZ |
| `visibility` | `V_VV`, `V_VV_I` | Видимость m и признак происхождения |

Все поля продукта, в том числе QN и буквенные индикаторы, сохраняются. Названия
и величины разных групп не сливаются. В частности, **`P0` — давление на высоте
станции; `P` — приведённое к уровню моря**. `P_STD` остаётся отдельной нативной
величиной и автоматически не подменяет `P0`. `VP_STD` — опубликованное парциальное
давление водяного пара; программа не вычисляет его заново из RH и температуры.

Точные описания, единицы и временные интервалы параметров сохранены в
`parameter_history`, а определения наборов — в оригинальных PDF. Некоторые
поля единиц в исторических метаданных DWD пустые; это состояние сохраняется,
и отсутствие записи не заменяется выдуманной единицей. `parameters.json`
содержит справочные единицы из описаний наборов с указанием источника.

## Скачать 2016–2025 годы

```bash
python germany_climate.py plan --config config_2016_2025.json --out plan_2016_2025.json
python germany_climate.py download --plan plan_2016_2025.json --out downloaded
```

По умолчанию выбираются `historical` и радиация `row`. `recent` не добавляется
автоматически поверх уже проверенных исторических наблюдений. Для ограниченной
первой порции:

```bash
python germany_climate.py download --plan plan_2016_2025.json --out downloaded --max-jobs 2
```

Повтор той же команды продолжает работу. Архив считается завершённым только
при совпадении задания и хешей исходного ZIP, обработанной CSV-части и разобранных
метаданных. Наличие файла само по себе не приводит к пропуску запроса.

Если опубликованный размер ZIP изменился по сравнению с планом, программа
отказывается смешивать версии. Обновите каталог, создайте новый план и используйте
новый выходной каталог. Ранее успешно скачанный снимок при возобновлении
сохраняется; программа не утверждает, что DWD не пересмотрел архив на сервере.

Запросы идут последовательно с паузой по умолчанию 1 с между началами. Это
собственная щадящая настройка программы, не заявленный лимит DWD. Есть ограниченные
повторы временных сетевых ошибок и HTTP 429/5xx. Долгий `Retry-After` выводится как
необходимость повторить позже. Не запускайте несколько процессов в одну папку
расчёта. После аварийного завершения удалять `.download.lock` можно только после
проверки, что предыдущий процесс остановлен. При обычном Ctrl+C блокировка снимается.

Пример своей конфигурации:

```json
{
  "start": "2020-01-01",
  "end": "2025-12-31",
  "groups": ["air_temperature", "pressure", "wind", "solar"],
  "station_ids": ["01048", "03987"],
  "tiers": ["historical", "row"],
  "min_interval_seconds": 1.0
}
```

Дата без времени: начало в 00:00 UTC, конец включает указанные календарные сутки.
Дата-время требует явного часового пояса; точный `end` задаёт **исключающую**
границу. Например, `end="2025-06-02T00:00:00Z"` завершает выбор перед этим часом.

## Время, пропуски и QC

CSV-части сохраняют все исходные поля и дополнительные колонки:

- `timestamp_source` — исходная временная метка без округления;
- `timestamp_utc` — UTC, если шкалу удалось разрешить по метаданным;
- `time_basis` — UTC, MEZ, WOZ, MOZ, UNKNOWN или AMBIGUOUS;
- `utc_status` — основание присвоения или преобразования времени.

При явно указанной MEZ применяется UTC+1 и фиксируется преобразование. При WOZ
(истинное солнечное время), MOZ, отсутствии или конфликте метаданных UTC остаётся
пустым. Такие строки отбираются по номинальным границам **исходных часов**;
отчёт прямо указывает, что точный UTC-период для них не подтверждён. Исторические
обозначения поставщика не являются независимой проверкой фактических часов.

В радиационном наборе основной `MESS_DATUM` и отдельный `MESS_DATUM_WOZ`
сохраняются раздельно; метаданные указывают UTC и WOZ. Метка основного ряда
может иметь минуты, например `00:02`. Она не округляется до `00:00`. Поэтому
сохранённые 24 строки ещё не означают 24 метки на целой UTC-часовой сетке.
Ресэмплинг, перенос часовых сумм между интервалами и переводы J/cm² в другие
энергетические единицы в этом модуле не выполняются.

Нативные значения `-999` и эквивалентные десятичные записи сохраняются в CSV.
Отчёт учитывает их как пропуски. Нули остаются нулями; отсутствующие строки
не добавляются. Например, набор солнечного сияния может не содержать ночные
строки. QN сохраняется и суммируется в отчёте, но не превращается в автоматический
допуск наблюдения. QC поставщика не равен гарантии отсутствия коррекций или
однородности многолетнего ряда.

## Результат и экспорт

```text
downloaded/<plan_id>/
  plan.json
  raw/<job_id>/<original_archive_name>.zip
  parts/<job_id>.csv.gz
  metadata/<job_id>.json
  receipts/<job_id>.json
  download_summary.json
  errors.jsonl
  stations/<station_id>/<group>/<year>.csv.gz
  stations/<station_id>/<group>/<year>.coverage.json
```

Папка расчёта использует первые 20 символов SHA-256 плана. Оригинальный ZIP
содержит полные метаданные приборов, алгоритмов и площадок; исходные члены ZIP
не извлекаются по неподтверждённым путям. Проверяются структура, station ID,
поля, `eor`, порядок и уникальность меток, конечность чисел, размеры и CRC.

Экспорт формируется отдельно по группе, чтобы сохранить её определения:

```bash
python germany_climate.py export --plan plan_2016_2025.json --out downloaded --station-id 01048 --year 2025 --group air_temperature --plain-csv
```

Без `--plain-csv` получается gzip CSV. Если обязательное задание станции/группы/года
ещё не скачано или повреждено, экспорт блокируется. Если план явно включает оба
раздела, при одинаковом UTC-времени приоритет имеет `historical`; пересечения и
расхождения подсчитываются. Конфликт внутри одного раздела приводит к отказу.

Отчёт разделяет выбранный календарный период, строки, отсутствующие UTC-метки,
неразрешённое/дробное время, непустые значения и QC по каждой величине. Полная
ось меток и полный метеорологический год — разные утверждения; допуск к EPW
этот загрузчик не выдаёт.

## Обновить каталог

```bash
python germany_climate.py catalog --out catalog_updated
python germany_climate.py nearest --catalog catalog_updated/catalog.json.gz --lat 52.52 --lon 13.405 --date 2025-01-01 --groups pressure
python germany_climate.py plan --catalog catalog_updated/catalog.json.gz --config config_2016_2025.json --out plan_updated.json
```

Без `--catalog` используется поставленный снимок. Уже созданный план содержит
зафиксированные задания и происхождение источников, поэтому обновление каталога
его не изменяет.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тестовые ZIP — явно помеченные **производные фрагменты настоящих архивов DWD**:
исходные метаданные сохранены, продукт ограничен исходными метками 1 июня 2025.
URL, хеш исходного полного ZIP, хеш фрагмента и преобразование находятся в
`tests/fixtures/provenance.json`. Отрицательные тесты изменяют копии в памяти;
эти копии не выдаются за наблюдения. Автономные тесты не обращаются к сети.
Сводка реальной загрузки полных исходных архивов приведена отдельно в `validation/`.
