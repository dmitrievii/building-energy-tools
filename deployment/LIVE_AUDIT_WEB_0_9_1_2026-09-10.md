## WEB-0.9.1 contrast closure

The preceding production audit had reported 3 desktop axe groups and 2 mobile groups. Exact DOM diagnosis established that the desktop-only `color-contrast` failure belonged to Streamlit's generated file-uploader hint:

```text
10MB per file • EPW
```

The failing computed foreground was:

```text
rgba(49, 51, 63, 0.6)
```

while the stable `stFileUploaderDropzoneInstructions` container inherited:

```text
rgb(49, 51, 63)
```

WEB-0.9.1 therefore applies a theme-safe override via the stable Streamlit test-id selector:

```css
[data-testid="stFileUploaderDropzoneInstructions"] span {
    color: inherit !important;
}
```

The post-merge audit reduced desktop axe groups from **3 to 2**, matching mobile, and the `color-contrast` group disappeared. The application-owned automated contrast finding is therefore:

```text
APP_UPLOADER_HINT_CONTRAST = CLOSED_LIVE
```

## Remaining accessibility findings

The two remaining reproducible axe groups are present on both desktop and mobile and are generated by Streamlit framework/platform markup:

1. `aria-allowed-attr` on `.stSidebar`;
2. `button-name` on a Streamlit toolbar action button.

They are retained as upstream/framework limitations. Building Energy Tools does not apply brittle generated-class DOM surgery merely to suppress an audit result.

Manual keyboard, focus-order and 200% zoom review remains required before public-promotion clearance.

Climate Analyzer defines none of those endpoints. The browser recorded:

```text
failed_requests = 0
page_errors     = 0
```

and the UI rendered and interacted normally. These responses are classified as Community Cloud wrapper/session/telemetry behavior, not Climate Analyzer API defects.

## Privacy-relevant production facts

Before map interaction the browser still observed provider-controlled Streamlit/Snowflake analytics/session infrastructure, including Google Analytics/Tag Manager, Heap and Segment-related domains and identifiers. This is distinct from Climate Analyzer source code, which does not add those services itself.

The lazy-map remediation remains effective:

```text
OSM_BEFORE_EXPLICIT_FIND_CLIMATE = FALSE
```

Therefore OpenStreetMap is no longer part of the initial visitor network footprint.
