# IGE: реестр программы E0–E8

Версия 1.0 от 2026-11-07. Это спецификация опытов и записей, а не готовый
вычислительный runner. Добавление этих файлов не запускает научные расчёты.

Позднейшее дополнение того же дня: локальный инженерный пакет E0/E1.0 реализован
в [tools/ige_climate_experiments](../../tools/ige_climate_experiments/README_RU.md).
Текущий статус и незакрытая часть legacy replay — в `EXECUTION_STATUS_20261107.json`.
Исходная v1-спецификация сохраняет состояние на момент её создания.

Дополнение **v1.1** по решению пользователя: старые коэффициенты проходят критическую
проверку, новая ветвь использует автоматический fit вместо основной ручной сетки.
Приоритет для E1 имеет `calibration_policy_v1_1.json`; математическая постановка —
[автоматическая калибровка](../../docs/IGE_AUTOMATIC_SPATIAL_CALIBRATION_RU_20261107.md).
Калибровщик пока не реализован. `program_v1.json` сохраняет первоначальный дизайн,
который следует читать вместе с этим явным дополнением.

Основной документ: [единая программа E0–E8](../../docs/IGE_EXPERIMENT_PROGRAM_RU_20261107.md).

| Файл | Назначение |
|---|---|
| `program_v1.json` | Гипотезы, controls, зависимости, gates, метрики и волны |
| `run_manifest.template.json` | Что зафиксировать до расчёта и дополнить после него |
| `source_register.json` | Происхождение решений и пределы уже известных результатов |
| `DECISIONS_RU.md` | Решения, изменения правил и статус незавершённых ветвей |

Значение `null` / `TBD` в новом плане означает нерешённый пункт, а не разрешение
выбрать его по ошибкам заключительной выборки. `DESIGNED` не означает, что все
адаптеры, модели и источники уже доступны. До большого запуска требуется отдельный
E0-отчёт и воспроизводимый E1.0-пилот. Все новые experiment/run IDs должны быть
уникальны; повторный расчёт получает отдельный attempt ID.

Поля `depends_on` задают обязательные зависимости. Условия в
`conditional_dependencies` применяются только к указанным утверждениям/ветвям.
`recommended_wave` задаёт порядок расходования ресурсов, а не запрет независимому
замороженному опыту стартовать раньше. SOURCE_BLOCKED одного варианта не блокирует
остальные опыты. Шаблон прогона не является JSON Schema; семантические требования
перечислены в `seal_requirements` реестра.

Рабочая последовательность:

1. Скопировать шаблон в новую карточку, заполнить источник, case universe, роль
   D/V/C, методы, параметры, статистику, бюджет и ожидаемую матрицу jobs.
2. Проверить и запечатать спецификацию по SHA-256; для C исключить доступ solver
   к значениям контроля и запечатать прогнозы до scoring.
3. Расчёт пишет только собственный output-каталог. Фиксированные inputs/cache
   доступны только для чтения. Неудачные и прерванные jobs остаются в отчёте.
4. После расчёта добавить результаты и фактические ресурсы отдельной записью,
   связанной хешем с запечатанной спецификацией. Исходную спецификацию не менять.
5. Сформулировать вывод с четырьмя отдельными статусами: численная корректность,
   физика/семантика, независимая точность, эксплуатация. Отрицательный результат
   и недостаточность данных сохраняются.

Крупные исходные данные, CSV прогнозов и симуляционные результаты не требуется
включать в git. В карточке нужны проверяемые пути/URI, размер, хеш, срок/способ
доступа и лицензия. Секреты доступа в реестр не входят. Воспроизводимость требует
наличия самих файлов: одного URI/хеша недостаточно, если источник утрачен.

Подготовленная программа сохраняет старые регистрации. В частности, IV1 не
становится новым почасовым опытом с другими QC/coverage gates задним числом.
